## Frozen protocol

`benchmark.json` freezes ten early facts, exact expected answers, the later current-state correction, distractor generation parameters, three repetitions, and adoption thresholds. `freeze.json` hashes the fixture, preparer/scorer, and this protocol. Freeze these in a commit **before either arm runs**. Never edit them in response to a result; make a new named benchmark version instead. Expected answers stay in the operator checkout and must never be accessible to the evaluated sessions.

```sh
python3 evals/agent-workflow/context-retention/benchmark.py prepare /tmp/bae-retention-inputs-v1
python3 -m unittest discover -s evals/agent-workflow/context-retention -p 'test_*.py'
```

Preparation is offline and refuses to overwrite an output directory. It writes three deterministic session directories, each with a session JSON and 48 synthetic diagnostic files. There are 51 user turns each: early facts; 48 requests to read long intervening diagnostic files; a fresh verified source excerpt; then the ten probes. The diagnostic payload per session exceeds 300 KB. These actual local file reads supply eligible tool-call/output pairs for Jev pruning; a messages-only fixture would not exercise that mechanism. Byte length is **not a token measurement**, and length alone is not proof of compaction. The filler is synthetic and repetitive; this is a pilot, not a broad estimate of real coding performance.

## Evidence format and scoring

`run.json` contains `benchmark_hash` (the SHA-256 of benchmark.json) and six `sessions`. Each record contains:

- `arm`: native or jev; `repetition`: 1–3; `kind`: real_codex; exact `model`, `model_service`, `codex_version`, `reasoning_effort`.
- `session_sha256`: hash of the prepared session JSON bytes; `trace_file`, `trace_sha256`, and `answer_file`: relative local files. The trace must preserve full turns, compaction, actions, and hook evidence.
- `compaction_verified`, `blinded_review_verified`, `reviewer`, `compaction_evidence`: the review attestation and exact event/line citation. `restoration_verified` is false for native, true for Jev; Jev also requires the pinned `tool_sha`.
- `labels`: one entry for each case ID, with explicit booleans for `hallucinated_detail`, `repeated_completed_work`, `violated_constraint`, `wrong_identifier`, `stale_context_preserved`, `restoration_noise`, plus a nonempty `evidence` citation. Label hallucination when an unsupported specific fact is invented; wrong identifier when the requested path/branch/PR/SHA is wrong; repeated work when the completed backend is proposed or performed again; stale preservation when superseded historical state is treated as current. Noise means irrelevant/wrong restoration is carried into the final response or decision; inspect restored content separately for omitted/redundant excerpts.
- `elapsed_ms`, `api_cost_usd`, `input_tokens`, `output_tokens`, `tool_calls`: actual measured numbers or null. Every measured value needs a `metric_evidence` citation keyed by the metric. Elapsed time spans first submitted turn through final response and includes compaction. Cost includes measured model plus Jev API charges; report component bills in evidence. No price estimates. Null is not zero.

Primary rate: fully correct case outcomes / 30 case outcomes per arm. Exact matches require correct JSON types; partially matched objects receive no full-credit point. A contradictory action or error label overrides literal correctness. Output records `correct`, `partial`, `forgotten` (no matching fields), or `failed` (reviewed error), with independent error flags. A nonmatch alone cannot diagnose the model's internal memory; these labels describe observed outcomes.

Violation, repeated-work, hallucination, stale-preservation and restoration-noise rates use all 30 cases as denominator; include raw case flags so category-specific rates can also be inspected. Exact identifier recall uses the six path/identity outcomes. Preserve individual case results rather than reporting only averages. Latency and usage means are null unless every session supplies that metric. Setup/maintenance complexity is reported qualitatively in TOOL_VERIFICATION.md.

Adoption thresholds were chosen before any model result: at least 20 percentage points gain in retention; a strict decrease in serious constraint violations; zero stale-context errors; restoration-noise rate no higher than 5%; latency ratio no higher than 1.25; added measured API cost no higher than USD 0.10/session; acceptable setup/maintenance complexity on independent review. Zero native violations cannot satisfy a strict decrease: that pilot remains TEST FURTHER. These are pilot decision thresholds, not a statistical significance test.

The scorer always emits TEST FURTHER pending independent review. With completed credible side-by-side evidence, the operator may record ADOPT only when every bar is met, REJECT for a demonstrated failure of the bars, or TEST FURTHER for unavailable metrics/inconclusive evidence. A restoration that preserves stale information fails the adoption bar regardless of text volume.
